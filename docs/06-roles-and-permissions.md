# 角色与权限

## 1. 管理层

### 关注

- 产品 Roadmap
- 项目整体状态
- 项目进度与延期
- 高风险项目
- Critical Issue
- Release Readiness

### 核心问题

> 哪些事情需要我关注和决策？

## 2. 产品经理

### 关注

- Market
- Customer
- Opportunity
- Roadmap
- Product
- Requirement
- Specification
- Version / Release

### 核心问题

> 产品是不是做了正确的东西？

## 3. 项目经理

### 关注

- Project
- Phase
- Milestone
- Task
- Dependency
- Schedule
- Risk
- Issue
- Change

### 核心问题

> 项目能不能按计划完成？

## 4. 技术负责人

### 关注

- Specification
- Architecture
- Technical Risk
- Issue
- Change
- Verification
- Decision

### 核心问题

> 技术方案是否正确，主要技术风险在哪里？

## 5. 验证负责人

### 关注

- Requirement Traceability
- Verification
- PASS / FAIL / BLOCKED
- Coverage
- Regression
- Issue

### 核心问题

> 产品是否被充分验证？

## 6. 工程师

### 关注

- My Tasks
- Blocked Tasks
- Due Date
- Issue
- Action Item

### 核心问题

> 我现在需要做什么，什么事情阻塞了我？

## 7. 权限原则

权限应围绕“查看、创建、修改、审批、关闭、发布”等业务动作设计，而不是简单复制数据库权限。

高风险动作应有明确责任人和审批记录，尤其是：

- Baseline 批准
- Requirement / Specification 冻结
- Change Approval
- Release Approval
- EOL 决策
